# Host `src/SVNAssist.Host` (net472, in-proc)

Package VSSDK classico (`AsyncPackage`) con due tool window ("SVN Changes", "SVN Log") che ospitano la UI web in WebView2, un relay verso `SVNAssist.Backend.exe` (StreamJsonRpc su stdio) e i comandi `.vsct`. Contratto: `src/Shared/RpcContract.cs`.

## Build
```
dotnet publish src/SVNAssist.Backend -c Release -o src/SVNAssist.Backend/bin/publish   # framework-dependent
dotnet restore src/SVNAssist.Host
msbuild src/SVNAssist.Host/SVNAssist.Host.csproj -p:Configuration=Release              # -> bin/Release/net472/SVNAssist.vsix
```
- Il VSIX contiene `ui/` (= `src/SVNAssist.UI.Web` senza `contract/`) e `backend/` (= `BackendPublishDir`, default `src/SVNAssist.Backend/bin/publish`; si cambia con `-p:BackendPublishDir=C:\dir\`). Senza backend la build avvisa e il VSIX non lo contiene.
- Con il MSBuild di VS 18 senza `MSBuild.exe.config` usare il launcher `tools/msb.cs` (compilarlo con `csc`: esegue MSBuild in un AppDomain con la config presa dal template; vedi `webview2-spike.md`). La versione del manifest deve coincidere con `Directory.Build.props` (la build fallisce se no).
- Test in VS: installare il `.vsix` in un'istanza sperimentale (`VSIXInstaller /rootSuffix:...`), poi `devenv /rootsuffix ... /updateconfiguration`. Log dell'host: `%LOCALAPPDATA%\SVNAssist\host-log.txt`. I comandi hanno nome (`SVNAssist.Changes`, `SVNAssist.Log`, ...).

## Comportamento
- Il backend parte alla prima vista/comando (non all'avvio di VS), muore con VS (Job Object KILL_ON_JOB_CLOSE), si riavvia se cade (max 4/min) e l'host rimanda `ready` di ogni vista, `SolutionChangedAsync`, `ThemeChangedAsync` e l'evento `backendRestarted`.
- Relay: pagina -> `IBackend.DispatchAsync(view, json)` (solo `ready` e `cmd`); backend -> `IHost.PushAsync(view, json)`. Il backend deve coalescere gli `state` (~16 ms), l'host non lo fa. Se il backend non risponde l'host manda `reply ok:false` / toast.
- Tema: `ThemeBridge` manda `theme{kind,vars}` al `ready`, a `VSColorTheme.ThemeChanged`, a cambio `windowTheme`; solo le variabili derivabili da VS (sfondi, testi, bordi, selezione, link, font): colori di stato/diff/sintassi restano quelli di `tokens.css` per il `kind`. Alto contrasto: colori di sistema.
- Impostazioni: Tools > Options > SVNAssist (chiavi camelCase del contratto; `GetSettingsAsync` ritorna anche gli alias minuscoli della 0.1.0). Le API key sono cifrate con DPAPI nel registro.
- **Log come documento**: `LogToolWindow` e' registrata con `ProvideToolWindow(Style = VsDockStyle.MDI, Transient = true)`: `ShowToolWindowAsync` la apre come tab nell'area editor (grande, come i diff) e non viene ripristinata al riavvio di VS. E' un'unica istanza: un nuovo percorso ne aggiorna titolo (`Pane.Caption = "Log: <cartella o file>"`) e contenuto invece di aprire tab separati (scelta piu' semplice e affidabile con una WebView2 per finestra).
- `IHost.ShowLogAsync(path)` apre il documento Log col titolo del percorso e inoltra `logLoad{path}`.
- `IHost.ShowFolderDiffAsync(path)` mostra la finestra Log e inoltra `logFolder{path}` (elenco dei file modificati della cartella; clic = diff nativo). `OpenDiffAsync` (`IVsDifferenceService.OpenComparisonWindow2`) apre ogni diff: file della working copy (BASE ↔ working copy), file di una revisione (`r-1 ↔ r`) e confronto tra due revisioni, con file temporanei in `%TEMP%\SVNAssist\diff` (esportati con `svn export -r`, cancellati alla chiusura del backend, quelli orfani dopo un giorno). TortoiseSVN non e' mai necessario.
- Menu: Extensions > SVNAssist (Changes, Commit..., Update, Update to revision..., Switch..., Merge..., Cleanup, Log). Nessun menu SVN in Solution Explorer (rimosso: ridondante con Changes). Menu contestuale dell'editor di codice: **SVN: Revert Selected Changes** (`CmdRevertSel`, anche nel pannello destro del diff, che e' il file di lavoro vero); **Next/Previous Change in Diff** (`CmdNextChange/CmdPrevChange`, Ctrl+Alt+Giu' / Ctrl+Alt+Su' nello scope editor di testo) eseguono i comandi VS `Diff.NextDifference` / `Diff.PreviousDifference` via DTE e fuori da un diff non fanno nulla. "Update" del menu Extensions invia il cmd `update` alla vista `changes`.

## Aggiunte al contratto (rispetto alla prima versione)
- `IBackend.ThemeChangedAsync(string kind)`.
- **SVN Switch**: nessun metodo RPC nuovo. Il comando `.vsct` `CmdSwitch` (0x0107, Extensions > SVNAssist > Switch...) invia `cmd switchOpen` alla vista `changes` (come Update to revision); selettore, svn e conferme stanno nel backend (comandi `switchOpen|switchRefresh|switchCancel|switchOk` in `docs/ui-protocol.md`). Nuova impostazione `repoLayout` (Tools > Options > SVNAssist > Generale), passata con `GetSettingsAsync`.
- **SVN Merge**: il comando `.vsct` `CmdMerge` (0x0108, Extensions > SVNAssist > Merge...) invia `cmd mergeOpen` alla vista `changes` (come Switch); la scelta della sorgente, svn, i conflitti e "Annulla merge" stanno nel backend. Metodo RPC nuovo **`IHost.ShowLogWindowAsync(title)`**: apre il Log come documento con quel titolo (`Pane.Caption`) **senza** inoltrare `logLoad`; lo usa il backend per "Merge da branches/x" (il contenuto del Log in modalita' merge lo ha gia' impostato lui) e per tornare a "Log: cartella" con Chiudi merge. Comandi e snapshot in `docs/ui-protocol.md` ("Log: modalita' merge").
- **Conflitti**: metodo RPC nuovo **`IHost.ShowChangesWindowAsync()`** (porta in primo piano SVN Changes: dopo "Risolvi ora" e dal pulsante "Risolvi i conflitti" del Log). L'editor di merge a 3 vie lo avvia il backend (non serve l'host): `vsDiffMerge.exe` del VS ospite (variabile `VSAPPIDDIR`, ereditata dal backend) o di un'installazione sotto `Program Files\Microsoft Visual Studio\<versione>\<edizione>\Common7\IDE\CommonExtensions\Microsoft\TeamFoundation\Team Explorer` (prima "18", poi 2022, 2019), altrimenti `TortoiseMerge.exe`, altrimenti il file con i marcatori in VS (`OpenFileAsync`). Argomenti di vsDiffMerge: `theirs mine base merged /m`.
- `IHost.PromptTextAsync(message, label, default)`: dialogo con un campo di testo (revisione, messaggio di lock); `null` se annullato. `IHost.PromptCredentialsAsync(detail, defaultUser)`: dialogo utente/password (password mascherata, "Ricorda" attivo di default) → `[utente, password, "1"|"0"]` o `null`; mostrato solo dopo un errore di autenticazione di svn, mai loggato.
- `IBackend.RunPathCommandAsync(string command, string[] paths)`: comandi su percorsi (`update|add|revert|diff|ignore|log|commit|updaterev|cleanup|lock|unlock`; non piu' collegati a menu: il menu di Solution Explorer e' stato tolto) e **`revertlines`**, usato da "SVN: Revert Selected Changes": `paths = [file, "da-a"]` (righe 1-based del file di lavoro). L'host prende file e selezione dalla vista di testo attiva (`IVsTextManager.GetActiveView`), salva il documento se modificato e il backend (`LineRevert`) calcola dal `svn diff` quali blocchi toccano le righe, li riporta a BASE preservando encoding/BOM/fine riga e riscrive il file (VS lo ricarica; niente Ctrl+Z). Messaggio "Annullate N righe" e refresh di Changes.
